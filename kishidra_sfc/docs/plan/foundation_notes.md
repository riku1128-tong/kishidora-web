## S1

- Mailbox protocol: write the args with `pokew dbg_arg …`, then `poke dbg_cmd N`, then `waitfor dbg_seq K` (dbg_seq goes up by 1 per command) and read dbg_ack and dbg_res. Unknown commands get ack 0xff. To add a command, add a `case` in dbg_poll (sys.c) and a DC_ number in sys.h. A command for one screen should check dbg_scr (the screen sets it with DBG_SCREEN(DS_…)) and call that screen's non-static handler directly. A function pointer does not work across banks, because the address taken inside a bank is the bank-local f__b.
- Non-static test-only functions can now sit inside `#ifdef TEST_HOOKS` anywhere: build.py makes trampolines only for functions that were compiled.
- XDEFS values that are not numbers (FORCE_WAVE=0,0,6) reach C only. ca65 gets bare names as =1 and numeric values as given.
- A TEST_HOOKS ROM has the same screens as the release ROM, but its audio is shifted by about 2 samples (0.06 ms; checked on the reg2 battle wav, the same after alignment). Do A/B audio between ROMs built with the same XDEFS, or use --wav-tol.
- abtest compares `peek` output by value with the WRAM offset dropped, so peeks survive code that moves. Each ROM's symbols come from its own .lbl or .map next to the .sfc: keep base.sfc together with base.map / base.lbl when copying ROMs.
- Scripts for TEST_HOOKS ROMs should have a `#!needs dbg_cmd` line, so that `abtest … tools/harness/t/` on release ROMs skips them instead of failing.
- Use `python3 tools/harness/hrun.py SCRIPT DIR` to turn a t/ script (with #!mksave) into a plain runrom script for textcheck.py or prof.py.
- Reference numbers for later lag checks, money stage (t/pre_money.txt, 900 frames): release 0.0 % lag; PROFILE 1.6 % (battle loops 886 / 900), nmi_vmax 258. oamlines worst: 22 slivers / 10 sprites per line.
- Scratch outputs are in /tmp/claude-0/-home-user-kishidora-web/bfba2c3a-727d-51a5-9268-545e956e9958/scratchpad/impl/S1/: base.sfc / base.map and base_p.* (pre-S1 ROMs), th.* (TEST_HOOKS), thp.* (PROFILE+TEST_HOOKS), runrom.old, and the abtest result folders.
- (review) Release vs TEST_HOOKS ROMs are not audio-identical: reg2's battle wav RMS is 2750 vs 2749, because the extra code and BSS shift CPU timing relative to the SPC. Screens are identical. Later A/B runs must use the same ROM kind on both sides.
- (review) dbg_scr is never reset centrally. Once screens start calling DBG_SCREEN, a screen that sets it should restore it on exit, or mk_screen should reset it. That is a design note for A1 and later, not an S1 defect.

## S5

- Every #!mksave save is now v2, and a pre-S5 ROM sees it as no save. To A/B against a pre-S5 ROM, copy the scripts with `sed -E 's/^(#!mksave [^ ]+)/\1 --v1/'`. Expect identical screens; the battle audio runs one frame later (the battle-start save is 598 B longer).
- Timing: a v2 load reads 598 B more, so boot has one more lag frame, and frame_wait advances rnd() every frame. Battles from a v2 save and from a migrated v1 save therefore start from different RNG states, and RNG-dependent shots differ. Always A/B two ROMs with the same save version.
- S7: inv_solo_all() + save_write on a load without ST_SOLO will move the first v2 write from the battle start to the load. mksave writes story = 1 (ST_SOLO clear), so every harness save will trigger it. savetest.py's expected seq / slot values (battle start = slot B seq 2, reload = slot A seq 3, fallback, new game) must then be updated in S7 — update the checks, do not drop them.
- savetest.py drives title A → map A, A, A (sortie). A full bag writes through menu Y, UP (last row = タイトルへ), A, はい. If B2 / C5 / E1 change these routes, update TITLE / BATTLE / TO_TITLE in savetest.py.
- savetest.py imports mksave (mksave.V1_SIZE, V2_NINV, V2_FIELDS, …). A later field added to the v2 block must also go into mksave's V2_FIELDS and its value table; the 598 B length is asserted. A field in spare[64] whose zero value is right for older saves needs no SAVE_VER bump.
- SLOT_SNAP 0x3E00 is defined in save.c, ready for A15's tower record; slot bytes 9300..$3DFF are free (6,572 B).
- A v1 migration of 999 items costs about 3 lag frames per load, only until the first v2 write. If S7 / Z1 want it faster: the cc65 memmove of about 8 KB dominates.
- (review) Not an S5 defect, a note for S7: once S7 adds inv_solo_all + save_write on load (PLAN §2.2), loading a v1 save writes immediately. The battle start then becomes the second v2 write, so savetest.py's 'slot A still the v1 save' checks will need updating in S7.
